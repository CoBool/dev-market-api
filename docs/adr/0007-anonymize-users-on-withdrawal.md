# 0007. 회원 탈퇴는 삭제가 아니라 익명화

- 상태: 승인됨 (탈퇴 기능은 미구현)
- 날짜: 2026-10-08

## 배경
게시글·댓글의 작성자 관계(`writerId`)를 사용자 삭제 시 어떻게 할지 정해야 했다.

| 프로젝트 | 사용자 삭제 시 댓글 |
|---|---|
| Ghost, django-contrib-comments | SET NULL (댓글 유지, 작성자 비움) |
| Lemmy, 원본 Panda Market | CASCADE (같이 삭제) |

## 결정
- 회원 탈퇴 시 **User 행을 지우지 않고** 이메일·닉네임 등 개인정보를 익명화한다.
- 게시글·댓글의 작성자 관계는 `ON DELETE RESTRICT`(기본값)를 유지하고, `writerId`는 계속 필수다.

## 근거
- SET NULL은 `writerId`가 nullable이 되어 응답(`writer: null`)과 권한 확인 등 **코드 전반에 null 처리**가 생긴다.
- SET NULL만으로 개인정보 삭제가 끝나지 않는다. 어차피 익명화 작업이 필요하다.
- 작성자 관계가 유지되어 신고·분쟁 시 추적할 수 있다. 대화 흐름(댓글)도 유지된다.
- RESTRICT는 실수로 사용자를 물리 삭제하려 할 때 데이터를 지키는 안전장치가 된다.

## 결과
- 탈퇴 기능을 만들 때 함께 할 일:
  - 익명화 규칙 (이메일·닉네임 unique 제약을 지키는 값으로 바꾸기, 비밀번호 무효화)
  - **`JwtAuthGuard`에서 사용자 상태 확인 → 탈퇴·삭제된 사용자의 토큰은 401**
    (현재는 서명만 확인해서, DB에서 지운 사용자의 토큰으로 글을 쓰면 P2003 → 409)
