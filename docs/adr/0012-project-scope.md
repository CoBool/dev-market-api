# 0012. 프로젝트 범위: 원본 기능을 이식하되 API 형태는 호환하지 않는다

- 상태: 승인됨
- 날짜: 2026-10-09

## 배경
이 프로젝트는 판다마켓 API(코드잇 스프린트 미션, Express + tsoa + inversify + Prisma 5)를 NestJS로 옮기고 있다.
원본과 비교해 보니 경로(`/auth/signUp`), 목록 쿼리(`pageSize`), 응답(`{ list, totalCount }`),
삭제 응답(200 `{ id }`), 에러 형태(`{ message }`)가 이미 다르다.
원본 프론트엔드와 호환할지, 원본에 없는 기능(거래 상태, 채팅 등)을 넣을지 기준이 필요했다.

## 결정

| 구분 | 기준 |
|---|---|
| **기능 범위** | 원본(`main` 브랜치)을 따른다. 원본에 없는 기능은 이식이 끝난 뒤에 다룬다 |
| **품질** | 우리 기준. 원본보다 낫게 (검증, 권한, 에러 처리, 보안, 테스트) |
| **API 형태** | 원본 프론트엔드와 **호환하지 않는다.** 경로·쿼리·응답 형태는 원본을 참고하되 ADR로 정한다 |

진행 순서: 원본 이식 완료 → 이식 결과를 바탕으로 **새롭게 해석한 판다마켓**으로 확장.

## 근거
- 목표는 **NestJS 학습**이지 기존 프론트엔드 연결이 아니다. 호환을 위해 Nest 관례나 이미 정한 ADR
  (0001 `{ items, meta }`, 0008 경로)을 되돌릴 이유가 없다.
- 기능 범위를 원본으로 묶으면 "이식 완료"라는 끝이 분명해지고, 고민이 기능 기획이 아니라 Nest 구현에 집중된다.
- 나중에 바꾸기 비싼 결정(응답 형태, 테이블 구조, 인증 구조)은 이미 정해 두었고,
  원본에 없는 확장(거래 상태, 동네, 채팅)은 대부분 컬럼·모듈을 **덧붙이는** 변경이라 미뤄도 비용이 작다.

## 결과
- 원본과 다른 경로·응답 형태는 **의도한 차이**다. 버그로 보지 않는다.
- 원본에서 가져올 것: CORS, API 문서(Swagger), 좋아요 수를 관계 개수로 다시 세는 방식, 정렬 동점 처리(`id` 보조 정렬),
  API별 테스트 파일 구성.
- 원본에서 따라 하지 않을 것: 같은 secret의 access/refresh 토큰, salt 없는 sha512 비밀번호, 이메일 존재를 드러내는 로그인 메시지,
  작성자 삭제 시 Cascade, 트랜잭션 밖의 좋아요 확인, 업로드 후에 하는 이미지 크기 검사.
- 남은 이식 순서: seed → 상품(태그·이미지) → 상품 댓글 → 좋아요(선택적 인증) → 이미지 업로드 → 사용자 API → 마무리(CORS, README, Swagger, `main` 병합, 태그).
